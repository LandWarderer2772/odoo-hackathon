================================================================================
AETHERIA BACKEND API & FRONTEND INTEGRATION WORKFLOW SPECIFICATION
================================================================================
Version: 1.0.0
Base URL: http://localhost:4000
Frontend Routing: http://localhost:3000/[tenantSlug] (e.g., /brightloop, /technova)
Auth Scheme: Bearer JWT Token in "Authorization: Bearer <token>" header OR "token" HttpOnly Cookie

--------------------------------------------------------------------------------
1. GLOBAL CONVENTIONS & HEADERS
--------------------------------------------------------------------------------
All API responses follow a uniform JSON structure:
Success Response:
{
  "success": true,
  "message": "Optional human-readable message",
  "data": { ... } or [ ... ],
  "meta": { ... }
}

Error Response:
{
  "success": false,
  "message": "Error description",
  "errors": [ { "field": "email", "message": "Invalid email address" } ]
}

Tenant Resolution Modes:
1. Path-Based (Preferred for public portal):
   GET /api/t/:tenantSlug/plans
   GET /api/t/:tenantSlug/products
2. Header-Based (Alternative for API clients):
   x-tenant-slug: brightloop
3. Token-Based (Automatic for authenticated requests):
   The backend resolves business_id automatically from the user's verified JWT.

4. USER JOURNEY 2: AUTHENTICATION & SESSION
--------------------------------------------------------------------------------
Step 2.1: Login
Endpoint: POST /api/auth/login
Body:
{
  "email": "admin@brightloop.com",
  "password": "Brightloop@12345!",
  "tenantSlug": "brightloop" // Optional, verifies tenant membership
}
Response Data:
{
  "token": "eyJhbGciOiJIUzI1NiIsIn...",
  "user": {
    "id": "user-uuid",
    "email": "admin@brightloop.com",
    "firstName": "Sarah",
    "lastName": "Connor",
    "role": "BUSINESS_ADMIN",
    "businessId": "tenant-uuid"
  },
  "business": {
    "id": "tenant-uuid",
    "name": "Brightloop Software",
    "slug": "brightloop",
    "primaryColor": "#4F46E5"
  }
}
Frontend Action:
Store token in memory/localStorage or read from HttpOnly cookie. Redirect to:
- If role === 'CUSTOMER': /brightloop/portal
- If role === 'BUSINESS_ADMIN' or 'STAFF': /brightloop/dashboard

Step 2.2: Get Current Session Profile
Endpoint: GET /api/auth/me
Headers:  Authorization: Bearer <token>
Response: Returns current authenticated user and tenant profile.

Step 2.3: Register a New Tenant (Self-Serve Business Onboarding)
Endpoint: POST /api/auth/register
Body:
{
  "businessName": "Acme Subscriptions",
  "slug": "acme",
  "email": "owner@acme.com",
  "password": "SecurePassword@123!",
  "firstName": "John",
  "lastName": "Doe",
  "phone": "+1 555-9988",
  "primaryColor": "#2563EB",
  "secondaryColor": "#1E293B"
}
Response: 201 Created with JWT token and created Business and Admin User.

Step 2.4: Real-time Slug Availability Check (During Registration Typing)
Endpoint: GET /api/tenants/check-slug/:slug
Example:  GET /api/tenants/check-slug/acme
Response: { "slug": "acme", "isAvailable": true }

Step 2.5: Password Reset Flow
Request Token:
POST /api/auth/forgot-password
Body: { "email": "user@example.com" }
Response: { "message": "...", "resetToken": "crypto-token-string" }

Submit New Password:
POST /api/auth/reset-password
Body: { "token": "crypto-token-string", "newPassword": "NewPassword@123!" }

--- D. SUBSCRIPTION LIFECYCLE FSM ---
1. List Subscriptions:
   GET /api/subscriptions
2. Transition State:
   PATCH /api/subscriptions/:id/status
   Body: { "action": "CONFIRM" } // Valid actions: CONFIRM, PAUSE, RESUME, CLOSE
3. Auto-Convert Accepted Quotation into Subscription:
   POST /api/quotations/:id/convert

--- E. INVOICING & PAYMENT LEDGER ---
1. Trigger Scheduled Recurring Billing Run (Midnight Billing Engine):
   POST /api/invoices/process-recurring-billing
   Response: Scans all active subscriptions due for renewal, advances billing dates,
   and generates new invoices with tax and discount calculations.

2. Record a Payment & Allocate Against Invoice:
   POST /api/payments
   Body:
   {
     "invoiceId": "inv-uuid",
     "amount": 100.00,
     "method": "BANK_TRANSFER", // BANK_TRANSFER, CREDIT_CARD, CASH, CHECK
     "notes": "Wire transfer received"
   }
   Response:
   Automatically updates invoice status:
   - Partial payment -> status becomes "PARTIALLY_PAID"
   - Settled in full -> status becomes "PAID"
   - Overpayment (> remaining balance) -> rejected with 400 Bad Request

7. ENTERPRISE BYODB (BRING YOUR OWN DATABASE / TAILSCALE)
--------------------------------------------------------------------------------
Tenants can optionally self-host their database and connect via Tailscale private IP.

1. Test Connection:
POST /api/tenants/test-db
Headers: Authorization: Bearer <admin_token>
Body:
{
  "connectionUrl": "postgresql://postgres:secret@100.64.0.10:5432/brightloop_db"
}
Response:
{
  "success": true,
  "message": "Self-hosted database reachable",
  "data": { "success": true, "latencyMs": 42 }
}

2. Save Custom DB URL:
PATCH /api/tenants/:id
Body:
{
  "customDbUrl": "postgresql://postgres:secret@100.64.0.10:5432/brightloop_db"
}
Result:
Subsequent requests to /brightloop automatically route to their private DB.
